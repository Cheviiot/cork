# Флаги configure для сборки Wine под cork. Единственный источник правды:
# читается и tools/wine/build.sh, и CI. Пустые строки и строки с # игнорируются.
#
# Смысл набора: инструменты MSVC, которые мы запускаем (cl, link, lib, rc, midl,
# mc, mt, dumpbin, ml, ml64, nmake, armasm, MSBuild), консольные. Им не нужен
# ни X11, ни звук, ни видео, ни Vulkan, ни USB, ни Bluetooth. Выбрасывая это на
# этапе configure, мы убираем и соответствующие библиотеки из зависимостей
# рантайма — у собранного wine/wineserver в ldd остаётся практически одна libc.
#
# Прежде чем добавлять сюда --without-<что-то> ещё, стоит убедиться, что это
# действительно не нужно MSBuild: он тянет за собой Mono, а тот заметно
# капризнее консольных инструментов.
#
# Ложный след, проверенный дважды, чтобы не проверять в третий раз. Если
# `cl /FS` отказывает с `C1902: Program database manager mismatch`, а Wine
# при этом печатает «no schannel support», «Failed to start SamSs service» и
# «Failed to get security packages list», то дело не в --without-gnutls,
# --without-gssapi и --without-krb5. Эти три флага снимались, Wine
# пересобирался с gnutls и krb5 — отказ остался прежним. Все три сообщения
# означают лишь, что службы префикса ещё не поднялись. Когда они подняты, та
# же урезанная сборка Wine перечисляет и Negotiate, и NTLM, и /FS проходит.
# Настоящая причина и замеры — в docs/generations.md, раздел «/Zi /FS и
# запуск служб префикса».

# i386 здесь не ради 32-битного хоста, а ради целей x86: собранный для них
# .exe должен запускаться и проверяться на месте, а не только уезжать на
# Windows. Без i386 такой файл компилируется и линкуется, но при запуске Wine
# не находит syswow64/ntdll.dll и падает ещё до main. Цена — заметно более
# долгая сборка Wine и больший рантайм; цена отсутствия — цель x86, проверить
# которую нечем.

--disable-win16
