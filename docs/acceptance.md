# Приёмка

Что должно работать, прежде чем Cork считается выпускаемым. Проверяется на
настоящем MSVC, настоящем Wine и настоящих сборках — то есть не в CI на каждый
коммит, а отдельным прогоном.

```bash
tools/acceptance/run.sh --report acceptance-$(date +%F).md
```

Без установленного тулчейна прогон откажется работать и скажет об этом;
`--install` сначала скачивает и устанавливает. `--list` перечисляет случаи,
имена случаев в аргументах ограничивают прогон ими. Ogre3D идёт только по
`--with-ogre`: он один занимает больше времени, чем всё остальное вместе.

Ночью то же самое делает `.github/workflows/e2e.yml`.

## Почему это отдельный скрипт, а не набор тестов

Приёмка отвечает не на вопрос «упало или нет», а на вопрос «что именно
работает на сегодня». Ответ на него — таблица, и её надо получать одной
командой и класть в отчёт целиком. Полтора десятка отдельных запусков этого не
дают: их результаты приходится сводить руками, а значит, их никто не сводит.

Второе: у предыдущей реализации e2e-тесты были, проходили ревью и **не
запускались в CI ни разу** — ни одна job не выставляла переменную, которая их
включала. Поэтому здесь ровно один вход и он безусловный: скрипт запускается,
его код возврата — код возврата job.

## Что проверяется

| Случай | Что именно |
|---|---|
| `doctor-quick` | быстрая проверка опубликованного поколения |
| `doctor-deep` | каждый файл сверяется с записанным дайджестом |
| `doctor-build` | компиляция и компоновка пробника на каждую цель |
| `hello-c` | `cl hello.c` со `stdio.h`, запуск, код возврата доезжает целиком |
| `hello-cpp` | C++ с `iostream`, Release и Debug; Debug обязан быть связан с отладочным CRT |
| `static-lib` | `lib.exe` собирает архив, `link.exe` его потребляет |
| `resources` | `rc.exe` компилирует `.rc`, ресурс читается из готового `.exe` |
| `manifest` | `mt.exe` встраивает манифест; повторный прогон не считается отказом |
| `response-file` | `@rsp` в UTF-16LE с BOM и путём с пробелом |
| `awkward-paths` | сборка в каталоге с кириллицей и пробелом |
| `targets` | x86, x64, arm64: тип машины в PE и фактический запуск |
| `cmake-ninja` | CMake + Ninja через поставляемый файл тулчейна |
| `msbuild` | настоящий `.vcxproj` |
| `incremental` | повторная сборка не делает ничего; правка одного файла пересобирает один. Заодно — единственный случай с настоящей параллельной сборкой в Debug, то есть с `/Zi /FS`: регрессия на `C1902` и `C1090`, см. docs/generations.md |
| `parallel` | две сборки одновременно, у каждой своя сессия, обе убираются |
| `offline` | сборка и запуск при полностью отсутствующей сети |
| `shared-lib` | DLL с импорт-библиотекой: собрана, слинкована, загружена при запуске |
| `pch` | предкомпилированные заголовки: `/Yc` создаёт, `/Yu` использует |
| `interrupt` | Ctrl-C посреди сборки: ни процессов Wine, ни каталога сессии |
| `ctest` | `ctest` запускает собранные `.exe` через `CMAKE_CROSSCOMPILING_EMULATOR` |
| `winsysroot` | clang-cl собирает по нашему дереву как по `/winsysroot` |
| `ccache` | вторая компиляция из кэша, объектный файл совпадает побайтово |
| `ogre` | Ogre3D 14.5.2, цель `OgreMain` |

## Что проверяется руками

Осталось два пункта. Остальные оказались автоматизируемыми, и лучше им быть
в матрице: проверка, которую надо помнить, рано или поздно не делается.

- **Сборка на ext4.** Reflink недоступен, клонирование префикса стоит настоящие
  полгигабайта. Ожидается одно предупреждение и предложение
  `CORK_PREFIX_MODE=shared`, а не молчаливое копирование на каждую сборку.
  Не автоматизировано, потому что нужна вторая файловая система, а
  подмонтировать её из приёмки нельзя без прав.
- **Размер до и после каждого этапа сокращения.** Записывается таблицей.
  Мерить `du` бесполезно: он приписывает разделённый экстент каждому файлу и
  показывает одно и то же до и после. Годятся `btrfs filesystem du -s`
  (колонка Exclusive) и разница свободного места.

Что перестало быть ручным:

- **Ctrl-C посреди сборки** — случай `interrupt`. Сборка из семнадцати единиц
  трансляции в Debug (то есть с `/FS`, то есть с живым сервером PDB)
  прерывается сигналом всей группе процессов, как из терминала. После этого
  проверяется, что процессов Wine этой установки не прибавилось и каталога
  сессии не осталось.

  Что проверка не пустая, подтверждено обратным опытом: тот же сценарий с
  `SIGKILL` вместо `SIGINT`, то есть без возможности прибраться, оставляет
  двадцать процессов вместо пяти и каталог сессии на месте.
- **`-j16` на большом проекте** — случай `ogre`: `cmake --build` без `-j`
  берёт все ядра, которых на этой машине шестнадцать.

## Куда идёт результат

`--report` пишет таблицу в файл, к ней — дату, версию Cork и версию хоста.
Без них отчёт бесполезен: «всё прошло» без указания, что именно и где, не
отличается от «не проверяли».

Подробный вывод каждого случая остаётся в `$CORK_HOME/acceptance/logs/` и
переживает прогон: в таблицу попадает строка, а разбираться приходится по
полному выводу. Упавший случай печатает последние двадцать пять строк сразу,
чтобы не искать их руками.
